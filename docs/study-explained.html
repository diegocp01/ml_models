What this study is

This is a data science thesis / portfolio project that explores crime records published by the City of Los Angeles. It mixes three classic ML toolkits:

  • Supervised learning — teach a model to label crimes as violent or not.
  • Unsupervised learning — look for natural groupings in the 2024 slice of the data.
  • Deep learning — try a small neural network on the same classification task.

The research framing is practical: help think about patterns in historical reports that might inform how analysts study risk and resource planning — not a live dispatch system.

What question it asks

The main modeling target is a yes/no label called violent_crime:

  • 1 = violent crime
  • 0 = non-violent crime

The model is asked: given a few facts about an incident (area, victim age/sex/descent, weapon description, and when it happened), can we predict whether it was coded as violent?

Features used for prediction: area name, victim age, victim sex, victim descent, weapon description, year, month, day, and hour. Crime-type text itself is used to define the violent label during preparation — it is not fed in as a prediction feature.

Cleaning highlights (plain English)

  • Dropped sparse secondary crime-code columns (crm cd 2/3/4) with very high missingness.
  • Filled many “weapon unknown” gaps with an explicit unknown category.
  • No duplicate rows were found in the saved run.
  • EDA notes that crimes are spread across the year (roughly ~70k–95k per month in the charts), with higher counts in areas such as 77th and Central.

What the notebook does (pipeline)

1
LoadDownload the LA crime CSV (or optionally pull via API).
2
Explore & cleanCheck types, missing values, duplicates; drop unhelpful columns; impute carefully.
3
Engineer featuresParse dates/times into year/month/day/hour; encode categories as numbers; build the violent/non-violent label.
4
Unsupervised dig (2024)Scale features, project with PCA + UMAP, then cluster with K-Means and DBSCAN.
5
Supervised modelsTrain logistic regression and random forest; tweak a couple of hyperparameters.
6
Deep learningTrain a small Keras network (Dense + Dropout) for up to 50 epochs.
7
PlaygroundInteractive widgets to try “what if” predictions for both forest and neural net.

Test set size in these runs: 192,602 rows (about 156,126 non-violent and 36,476 violent) — so the classes are uneven. That helps explain why logistic regression looks “fine” on accuracy but struggles to catch violent cases (low recall).

Unsupervised (2024 subset on UMAP space)

  • K-Means (4 clusters): silhouette score 0.554
  • DBSCAN: silhouette score 0.443

Higher silhouette ≈ somewhat clearer separation; K-Means scored better here than DBSCAN.

Deep learning

  • Architecture: Dense(128) → Dropout(0.3) → Dense(64) → Dropout(0.3) → Dense(1, sigmoid)
  • Trained up to 50 epochs with Adam + binary cross-entropy
  • Final reported validation accuracy: 0.8739 (~87.4%)
Takeaway in one sentence: Random Forest was the strongest practical classifier in this notebook, especially at finding violent crimes, while a neural net reached similar overall accuracy and logistic regression lagged on the minority (violent) class.

Caveats (please read)

Class imbalance. Non-violent cases dominate the test set; accuracy alone can look optimistic while violent-crime recall stays harder.
Historical reports ≠ future forecasting. The supervised task classifies characteristics of recorded incidents; it is not a live hotspot forecast of where the next crime will occur.
Data freshness. The public feed updates over time. Metrics here match the notebook’s saved run (~963k rows through early Aug 2024 coverage notes).
Sensitive attributes. Victim demographics are in the public dataset and were used as features. Interpret carefully; avoid stigmatizing communities from model outputs.
Weapon missingness. Many rows lack weapon info; unknowns were explicitly coded — that choice affects what the model “learns.”
Docs vs notebook. This explainer was written in a docs-only pass. The .ipynb file was not modified for these pages.
